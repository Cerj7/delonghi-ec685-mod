# Debug Repeater (`scripts/002_debug_repeater.cpp`)

Діагностичний скетч для Arduino Nano: зчитує штатні сигнали EC685, **повторює** керування ТЕНом (SDD → SSR) і помпою (штатний сигнал → AC-диммер), стримить CSV на ПК і показує **у реальному часі** натискання кнопок / відкриття ручки пари. Задача — [`debug-repeater.md`](../debug-repeater.md); крок 4–7 у [`readme.md`](../readme.md).

---

## Навіщо

1. Зрозуміти імпульси лічильника води (частота, наявність під час проливу).
2. Зіставити температуру (MAX6675) з циклами нагріву.
3. Переконатися, що passthrough ТЕНу **і** помпи не ламає штатні режими (прогрів, 1/2 cup, пар, промивка).
4. Бачити в live, коли натискають кнопки і коли відкривають подачу пари — щоб потім вирішити, чи режим еспресо видно лише по SDD/помпі, чи потрібні кнопки.

Потенціометри **не** використовуються: помпа йде строго за штатним сигналом (0 % / 100 %).

---

## Що робить скетч

| Блок | Поведінка |
| --- | --- |
| **Passthrough ТЕН** | Кожен оберт `loop`: читає `D6` (SDD), пише на `D4` (SSR). Активний SDD → `HEATER HIGH`. |
| **Passthrough помпа** | Читає `A3` (штатний сигнал помпи), пише на диммер `D3`: активний → `Dimm_value(255)`, інакше `0`. Zero-Cross на `D2`. |
| **Флоуметр** | PCINT на `D5`, лічильник імпульсів + `flow_hz` за вікном 200 мс. |
| **Термопара** | MAX6675 кожні 250 мс (`D11/D12/D13`). |
| **Кнопки / пар** | `D7–D10`: CSV + OLED; **одразу** при зміні стану — рядок `# EVT ...` у Serial. |
| **Serial** | CSV ~50 Гц + event-рядки, `115200`. |
| **OLED** | H/P ON, flow, °C, імпульси; нижній рядок — `[1][2][S][STEAM]` коли активні. |

## Піни

| Пін | Роль у цьому скетчі |
| --- | --- |
| `D2` | Zero-Cross диммера (фіксовано бібліотекою) |
| `D3` | GATE диммера → симистор помпи |
| `D4` | Вихід → оптопара штатного SSR ТЕНу |
| `D5` | Вхід імпульсів флоуметра (PCINT) |
| `D6` | Вхід штатного SDD (через оптопару) |
| `D7–D10` | Кнопки 1 cup / 2 cup / steam + ручка пари |
| `D11–D13` | MAX6675 (CS / SO / SCK) |
| `A3` | Вхід штатного сигналу помпи (через оптопару) |
| `A4/A5` | OLED I2C |

## Як знімати логи

1. Прошити Nano, підключити USB до ПК.
2. Serial Monitor, **115200 baud** (для подій кнопок зручніший Monitor, ніж Plotter).
3. Увімкнути кавоварку, прогнати idle → 1 cup → 2 cup → кнопка пару → ручка пари → пролив без кави.
4. Зберегти CSV+EVT (копіпаст або `cat /dev/ttyUSB0`).

### Формат CSV

```text
# EC685 debug-repeater
# t_ms,sdd,heater,pump_in,pump_out,flow_pulses,flow_hz,temp_c,btn1,btn2,btn3,steam
# EVT lines: button / steam_handle edge events
12340,1,1,1,1,56,12.50,91.25,1,0,0,0
# EVT 12355 1CUP PRESS | 1cup=ON 2cup=off steam_btn=off steam_handle=closed
# EVT 14800 STEAM_HANDLE OPEN | 1cup=off 2cup=off steam_btn=off steam_handle=OPEN
```

| Поле | Опис |
| --- | --- |
| `t_ms` | `millis()` |
| `sdd` | 1 = штатний сигнал «гріти» активний |
| `heater` | 1 = Arduino подає ON на SSR (має збігатися з `sdd`) |
| `pump_in` | 1 = штатний сигнал помпи активний (`A3`) |
| `pump_out` | 1 = диммер на 100 % (має збігатися з `pump_in`) |
| `flow_pulses` | Накопичений лічильник імпульсів з старту |
| `flow_hz` | Частота імпульсів за останні ~200 мс |
| `temp_c` | °C з MAX6675 або `nan` |
| `btn1/2/3` | 1 cup / 2 cup / кнопка steam |
| `steam` | Ручка пари відкрита |

Рядки з `#` — коментарі / події. Парсер CSV може їх ігнорувати; для live-спостереження читайте `# EVT`.

### Події `# EVT` (реальний час)

Друкуються **в тому ж `loop`**, де змінилася лінія — не чекають інтервалу CSV:

| Фрагмент | Значення |
| --- | --- |
| `1CUP PRESS/release` | Кнопка однієї порції |
| `2CUP PRESS/release` | Кнопка двох порцій |
| `STEAM_BTN PRESS/release` | Кнопка режиму пару на панелі |
| `STEAM_HANDLE OPEN/CLOSE` | Ручка подачі пари |
| `INIT ...` | Стартовий знімок станів після boot |

Після зміни події завжди йде короткий підсумок `| 1cup=... steam_handle=...`.

### OLED

`H:` / `P:` ON|off, `FL:`, `T:`, `N:`; знизу активні органи: `[1] [2] [S] [STEAM]`.

## Типові проблеми при знятті сигналів

| Симптом | Що перевірити |
| --- | --- |
| `sdd=0` завжди, ТЕН холодний | Оптопара SDD, полярність, чи розірвано штатний ланцюг і вставлено Arduino |
| `sdd` блимає, ТЕН не гріє / гріє навпаки | Інверсія виходу на SSR або `ACTIVE_LOW` |
| `pump_in=1`, помпа мовчить | Zero-Cross `D2`, GATE `D3`, живлення диммера 220 В, `Dimm_value` |
| `pump_in` і `pump_out` розходяться | Баг у скетчі / зависання між викликами (не має статися — оновлюються разом) |
| `# EVT` немає при натисканні | Оптопара кнопок, `ACTIVE_LOW`, чи лінія реально тягнеться до GND |
| `flow_hz=0` під час проливу | Фронт у ISR (RISING ↔ FALLING), підтяжка; чи `pump_out=1` |
| `temp_c=nan` | CS/SO/SCK, живлення MAX6675, холодний спай |
| Serial «рве» рядки | Інший baud; збільшити `LOG_INTERVAL_MS` (EVT лишаться окремо) |

## Аналіз небезпек для кавоварки

Скетч **вставляється в ланцюг ТЕНу і помпи**. Штатний MCU більше не керує SSR/симистором напряму — лише через Arduino. Це головне джерело ризику.

### Критичні

| Ризик | Чому виникає | Наслідок | Як знизити |
| --- | --- | --- | --- |
| **ТЕН «залип» у ON** | Зависання `loop` (I2C OLED, Serial), WDT відсутній; остання команда була HIGH | Перегрів термоблока; останній захист — штатний термозапобіжник (одноразовий) | Не лишати без нагляду; спочатку тест **без** підключеного SSR; додати WDT + timeout ON; апаратний термостат/запобіжник |
| **Помпа «залипла» у ON** | Те саме для диммера на 255 | Безперервний пролив / тиск на OPV | Спочатку тест без силового виходу диммера; `Dimm_value(0)` у `setup`; не прошивати під час проливу |
| **Інверсія полярності SDD/SSR або помпи** | Неправильна оптопара / `ACTIVE_LOW` | Постійний нагрів/пролив або повна відсутність | Пробник/світлодіод на `D4`/`D3` **до** силового підключення; звірити `sdd`/`pump_in` з реальним станом |
| **Втрата штатного термозахисту по софту** | Arduino ігнорує температуру для вимкнення; лише passthrough | Якщо passthrough збоїть, штатний алгоритм «бачить» свій вихід, але актуатори керуються інакше | Апаратна цілісність ланцюга |
| **Живлення / земля без розв’язки** | USB ПК + сигнали з плати DeLonghi на спільній землі | Пошкодження штатної плати або Nano | Оптопари на **всіх** лініях від штатної плати |

### Серйозні

| Ризик | Чому | Наслідок | Як знизити |
| --- | --- | --- | --- |
| **Спотворення duty cycle SDD / помпи** | `Serial` + OLED блокують `loop`; затримка passthrough | Інша середня потужність ніж задумав штатний MCU | Збільшити `LOG_INTERVAL_MS`; passthrough лишати першим у `loop` (уже так) |
| **Вікно boot / reset / прошивки** | При reset виходи спочатку INPUT, потім OFF у `setup` | Короткі провали нагріву/проливу | Зовнішній pull-down на вході оптопари SSR / GATE; не прошивати під час приготування |
| **`delay(500)` у `setup`** | ТЕН і помпа примусово OFF пів секунди | Збій лише старту | Прийнятно; не збільшувати |
| **Помилка врізання в лінію флоуметра/кнопок/помпи** | Напруга/струм у штатну лінію без оптопари | Пошкодження MCU кавоварки | Тільки через оптопару / узгоджений рівень |

### Помірні / низькі

| Ризик | Оцінка |
| --- | --- |
| Тиск / OPV | Як у стоку, якщо passthrough помпи вірний |
| Сухий хід ТЕНу | Як у стоку, якщо passthrough вірний |
| MAX6675 на корпусі термоблока | Ризик для машини низький |
| Переповнення `flow_pulses` | Лише артефакт логу |
| Хибна інтерпретація логів | Не ламає залізо |

### Чого в скетчі **немає** (свідомо)

- Watchdog (`wdt_enable`)
- Software cut-off за `temp_c`
- Максимальний час безперервного ON без зміни входу
- Буферизація логу в EEPROM/SD (лише live USB)
- Регулювання потужності помпи потенціометром (це скетч [`003`](../scripts/003_pump_dimmer_display.cpp))

## Рекомендований порядок першого запуску

1. **Без 220 В на ТЕНі / диммері:** перевірити, що `sdd` і `pump_in` у логу змінюються; що `# EVT` з’являються при кнопках і ручці пари.
2. Перевірити: при `sdd=0` → `D4` LOW; при `pump_in=0` → диммер 0.
3. Короткий цикл з підключеними актуаторами під наглядом: прогрів → одна порція → пар → вимкнення.
4. Лише потім довгі зйомки CSV для аналізу форми сигналу.
