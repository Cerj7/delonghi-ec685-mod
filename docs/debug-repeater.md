# Debug Repeater (`scripts/002_debug_repeater.cpp`)

Діагностичний скетч для Arduino Nano: зчитує штатні сигнали EC685, **повторює** керування ТЕНом (passthrough SDD → SSR) і стримить лог на ПК. Задача описана в [`debug-repeater.md`](../debug-repeater.md); крок 4–7 у [`readme.md`](../readme.md).

---

## Навіщо

1. Побачити форму сигналу штатного MCU на оптопару SSR термоблока (SDD).
2. Зрозуміти імпульси лічильника води (частота, наявність під час проливу).
3. Зіставити температуру (MAX6675) з циклами нагріву.
4. Заодно записати кнопки / ручку пари — щоб пізніше вирішити, чи режим еспресо видно лише по SDD, чи потрібні кнопки.

Помпа **не** перехоплюється: лишається під штатним контролером.

---

## Що робить скетч

| Блок | Поведінка |
| --- | --- |
| **Passthrough ТЕН** | Кожен оберт `loop`: читає `D6` (SDD), пише на `D4` (SSR). Активний SDD (оптопара тягне пін до GND) → `HEATER HIGH`. |
| **Флоуметр** | PCINT на `D5`, лічильник імпульсів + `flow_hz` за вікном 200 мс. |
| **Термопара** | MAX6675 кожні 250 мс (`D11/D12/D13`). |
| **Кнопки** | `D7/D8/D9/D10` лише в лог і на OLED (не впливають на виходи). |
| **Serial** | CSV ~50 Гц, `115200`. |
| **OLED** | Статус: SDD, flow Hz, °C, лічильник імпульсів, маска кнопок. |

Диммер і потенціометри **не** використовуються.

## Піни

| Пін | Роль у цьому скетчі |
| --- | --- |
| `D4` | Вихід → оптопара штатного SSR ТЕНу |
| `D5` | Вхід імпульсів флоуметра (PCINT) |
| `D6` | Вхід штатного SDD (через оптопару) |
| `D7–D10` | Кнопки / ручка пари (лог) |
| `D11–D13` | MAX6675 (CS / SO / SCK) |
| `A4/A5` | OLED I2C |

Повна таблиця — у [`readme.md`](../readme.md).

## Як знімати логи

1. Прошити Nano, підключити USB до ПК.
2. Serial Monitor / Plotter, **115200 baud**.
3. Увімкнути кавоварку, прогнати idle → 1 cup → 2 cup → пар → пролив без кави.
4. Зберегти CSV (копіпаст або `cat /dev/ttyUSB0`).

### Формат CSV

```text
# EC685 debug-repeater
# t_ms,sdd,heater,flow_pulses,flow_hz,temp_c,btn1,btn2,btn3,steam
12340,1,1,56,12.50,91.25,1,0,0,0
```

| Поле | Опис |
| --- | --- |
| `t_ms` | `millis()` |
| `sdd` | 1 = штатний сигнал «гріти» активний |
| `heater` | 1 = Arduino подає ON на SSR (має збігатися з `sdd`) |
| `flow_pulses` | Накопичений лічильник імпульсів з старту |
| `flow_hz` | Частота імпульсів за останні ~200 мс |
| `temp_c` | °C з MAX6675 або `nan` |
| `btn1/2/3` | 1 cup / 2 cup / steam |
| `steam` | Ручка пари |

Рядки з `#` — коментарі.

### OLED

`SDD:ON/off`, `FL:xx.xHz`, `T:xx.xC`, `N:` (імпульси), `B:12SH` (активні кнопки) + мітка `LOG`.

## Типові проблеми при знятті сигналів

| Симптом | Що перевірити |
| --- | --- |
| `sdd=0` завжди, ТЕН холодний | Оптопара SDD, полярність, чи розірвано штатний ланцюг і вставлено Arduino |
| `sdd` блимає, ТЕН не гріє / гріє навпаки | Інверсія виходу на SSR або `ACTIVE_LOW` |
| `flow_hz=0` під час проливу | Фронт у ISR (RISING ↔ FALLING), підтяжка, розв’язка |
| `temp_c=nan` | CS/SO/SCK, живлення MAX6675, холодний спай |
| Serial «рве» рядки | Інший baud, буфер; зменшити `LOG_INTERVAL_MS` навантаження не зменшить — навпаки збільшити інтервал |

## Аналіз небезпек для кавоварки

Скетч **вставляється в ланцюг керування ТЕНом**. Штатний MCU більше не керує SSR напряму — лише через Arduino. Це головне джерело ризику. Помпа й гідравліка залишаються штатними → ризики тиску/OPV від цього скетча мінімальні.

### Критичні

| Ризик | Чому виникає | Наслідок | Як знизити |
| --- | --- | --- | --- |
| **ТЕН «залип» у ON** | Зависання `loop` (I2C OLED, Serial), WDT відсутній; остання команда була HIGH | Перегрів термоблока; останній захист — штатний термозапобіжник (одноразовий) | Не лишати без нагляду; спочатку тест **без** підключеного SSR; додати WDT + timeout ON; апаратний термостат/запобіжник |
| **Інверсія полярності SDD/SSR** | Неправильна оптопара / `ACTIVE_LOW` / «HIGH = вимкнено» на виході | Постійний нагрів або повна відсутність нагріву при «нормальній» логіці штатного MCU | Пробник/світлодіод на `D4` **до** підключення силової оптопари; звірити `sdd` і реальний стан ТЕНу мультиметром на низьковольтній стороні |
| **Втрата штатного термозахисту по софту** | Arduino ігнорує температуру для вимкнення; лише passthrough | Якщо passthrough збоїть, штатний алгоритм «бачить» свій вихід, але реальний ТЕН керується інакше | Апаратна цілісність ланцюга; не вважати штатний NTC достатнім, поки SSR на Arduino |
| **Живлення / земля без розв’язки** | USB ПК + сигнали з плати DeLonghi на спільній землі | Пошкодження штатної плати або Nano, наводки, хибні спрацьовування | Оптопари на **всіх** лініях від штатної плати; заземлення корпусу; обережно з USB під час 220 В робіт |

### Серйозні

| Ризик | Чому | Наслідок | Як знизити |
| --- | --- | --- | --- |
| **Спотворення duty cycle SDD** | `Serial` + OLED блокують `loop`; затримка passthrough десятки мс | Інша середня потужність ТЕНу ніж задумав штатний MCU → перегрів/недогорівання в окремих режимах | Збільшити `LOG_INTERVAL_MS` (напр. 50–100); вимкнути OLED на критичних зйомках; винести passthrough вище за важкі виклики (вже першим у `loop`) |
| **Вікно boot / reset / прошивки** | При reset `D4` спочатку INPUT (підтяжки зовнішні?), потім `LOW` у `setup` | Короткі провали нагріву; рідко — короткий HIGH при поганій розводці | Зовнішній pull-down на затворі/вході оптопари SSR; не прошивати під час приготування |
| **`delay(500)` у `setup`** | ТЕН примусово OFF пів секунди після старту | Збій лише старту прогріву, не перегрів | Прийнятно; не збільшувати |
| **Помилка врізання в лінію флоуметра/кнопок** | Напруга/струм у штатну лінію без оптопари | Пошкодження MCU кавоварки | Тільки високоімпедансний вхід через оптопару / узгоджений рівень |

### Помірні / низькі

| Ризик | Оцінка |
| --- | --- |
| Помпа, тиск, OPV | Скетч помпу не чіпає — OK |
| Сухий хід ТЕНу | Як у стоку, якщо passthrough вірний |
| MAX6675 на корпусі термоблока | Ризик для машини низький; ризик удару/замикання — якщо спай торкає «живу» точку |
| Переповнення `flow_pulses` (`ulong`) | Лише артефакт логу після ~багато годин |
| Хибна інтерпретація логів | Не ламає залізо, але може підштовхнути до небезпечної фінальної прошивки |

### Чого в скетчі **немає** (свідомо / варто знати)

- Watchdog (`wdt_enable`)
- Software cut-off за `temp_c` (напр. > 150 °C → `HEATER LOW`)
- Максимальний час безперервного ON без зміни SDD
- Буферизація логу в EEPROM/SD (лише live USB)
- Повтор сигналу помпи (план у readme згадує помпу; цей файл — лише ТЕН)

## Рекомендований порядок першого запуску

1. **Без 220 В на ТЕНі / з від’єднаним силовим виходом SSR:** перевірити, що `sdd` у логу змінюється при прогріві штатної машини (якщо SDD ще паралельно видно) або симуляцією оптопари.
2. Перевірити, що при `sdd=0` на `D4` стабільно LOW (підтяжка вниз на вході оптопари SSR).
3. Короткий цикл з підключеним SSR під наглядом: прогрів → одна порція → вимкнення; порівняти поведінку з «до мода».
4. Лише потім довгі зйомки CSV для аналізу форми сигналу.
