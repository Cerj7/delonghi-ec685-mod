# Thermoblock PI Heater (`scripts/006_thermoblock_pi_heater.cpp`)

Прошивка для Arduino Nano: потенціометр температури (`A1`) задає цільову температуру термоблоку від **20 °C (кімнатна / холодний стан)** до **100 °C**, ПІ-регулятор за термопарою термоблоку тримає її, керуючи SSR ТЕНу (`D4`) часовим ШІМ. На OLED — температура термоблоку й **поточна потужність ТЕНу у %**. Кнопки не зчитуються.

| Пункт | Реалізація |
| --- | --- |
| Дисплей | Рядок 1 (великий): `Tt=93.3C`; рядок 2 (великий): `P=6%`; рядок 2 (дрібний): `S=93` |
| Задана T | `A1` → 20…100 °C, лінійно |
| ТЕН | `D4`, ПІ + часове ШІМ, вікно **1 с**, перерахунок кожні **100 мс** |
| Зворотний зв'язок | MAX6675 #1 (`CS = A2`) — термоблок, період 250 мс |
| Помпа | `A0` → 0…100 % → рівень диммера (як у `005`), на екран не виводиться |
| Термопара бачка | MAX6675 #2 (`CS = D11`) не читається, але CS тримається `HIGH` |
| Кнопки / ручка пари | Не зчитуються, лінії = `INPUT_PULLUP` |
| Watchdog | 2 с: зависання → reset → `D4` LOW, помпа 0 |

## Піни

| Пін | Роль у цій прошивці |
| --- | --- |
| `D2` | Zero-Cross диммера (жорстко всередині `AC_Dimmer`, INT0) |
| `D3` | GATE диммера → симистор помпи |
| `D4` | **SSR ТЕНу** — вихід часового ШІМ, `HIGH` = нагрів |
| `D5` | флоуметр — не використовується (вхід з підтяжкою) |
| `D6` | штатний SDD — не використовується (вхід з підтяжкою) |
| `D8` / `D9` | Кнопка 1 — не використовуються (входи з підтяжкою) |
| `D10` | ручка пари — не використовується (вхід з підтяжкою) |
| `A2` | CS термопари **#1 — термоблок** (регулятор і показ) |
| `D11` | CS термопари **#2 — бачок** (не читається, але примусово `OUTPUT` + `HIGH`) |
| `D12` / `D13` | SO / SCK — спільна шина MAX6675 |
| `A0` | потенціометр **помпи** (0…100 %) |
| `A1` | потенціометр **температури термоблоку** (20…100 °C) |
| `A4` / `A5` | OLED I2C (SDA / SCL) |

> Полярність виходу ТЕНу — як у `001.cpp`/`002_debug_repeater.cpp`: **`HIGH` = нагрів** (оптопара штатного SSR).
>
> ⚠️ **CS бачка (`D11`) обов'язково `OUTPUT` + `HIGH`.** Інакше «плаваючий» CS другого MAX6675 (спільна шина SO `D12`) конфліктує, і `readCelsius()` термоблоку повертає рівно `0.0`. Для регулятора це найнебезпечніший випадок (блок нібито «дуже холодний»), тому такий нуль додатково вважається **невалідним** — див. «Захист».

## Логіка

### Потенціометр → задана температура

- Опитування кожні **20 мс**: 8 відліків АЦП, середнє, експоненційне згладжування `POT_SMOOTHING = 0.3`.
- Шкала лінійна: `0 → 20 °C`, `1023 → 100 °C`. Тобто «кімнатна» — це не «нагрів до 20 °C», а **вимкнено** (див. нижче).
- `S=nn` на екрані — згладжене значення, щоб ручка читалась без стрибків.

### Нагрів вимкнений, коли

| Умова | Причина |
| --- | --- |
| `targetTempC ≤ 21 °C` | Ручка в мінімумі = «холодний стан». Інакше в прохолодній кімнаті ТЕН грів би блок до 20 °C |
| термопара невалідна | `NAN`, `≤ 1 °C`, `≥ 200 °C`, або «залиплий» нуль ≥ 3 читань поспіль |
| `Tt ≥ 105 °C` (`SAFETY_CUTOFF_C`) | Апаратний захист від перегріву/залипання симистора |

У всіх цих випадках ПІ-вихід = 0, **інтеграл скидається**, `D4` = `LOW`.

### ПІ-регулятор

```
error   = target - Tt
P       = Kp · error                    Kp = 5.0 %/°C
I      += Ki · error · dt               Ki = 0.05 %/(°C·с)  → Ti = 100 с
output  = clamp(P + I, 0 … 100)         % потужності ТЕНу
```

- **Мертва зона `±0.5 °C`** (`HEATER_DEADBAND_C`): усередині неї інтеграл «замерзає». MAX6675 має крок 0.25 °C, і без цього шум повільно накопичувався б в інтеграторі, а вихід «дихав» на кілька %.
- **Anti-windup**: коли вихід уже в насиченні й похибка штовхає його далі — інтеграл не накопичується. Без цього після холодного старту був би перегрів на 5–8 °C.
- Перерахунок кожні **100 мс**.

Коефіцієнти підібрані симуляцією (модель `C·dT/dt = P − k·(T − T_amb)`, маса 350–1100 г, потужність 900–1350 Вт, затримка датчика 3 с):

| Сценарій | Перерегулювання | Час до `S−1 °C` |
| --- | --- | --- |
| 700 г, 1350 Вт, ціль 93 °C | **+0.13 °C** | 41 с |
| 1100 г, 1350 Вт, ціль 93 °C | **+0.83 °C** | 67 с |
| 350 г, 1350 Вт, ціль 93 °C | −0.14 °C (без викиду) | 17 с |
| 700 г, 1350 Вт, ціль 100 °C | **+0.16 °C** | 45 с |
| 700 г, 1350 Вт, ціль 60 °C | **+0.59 °C** | 24 с |

### Часове ШІМ на SSR

- Вікно **1 с**: у перші `percent·10 мс` вікна `D4 = HIGH`, решта — `LOW`. Середня потужність = `percent` %.
- Ключ перемикається **кожен `loop`** (а не раз на 100 мс): інакше момент вимкнення квантувався б до 100 мс і на сталій потужності 6 % реально виходило б 10 % (100 мс із 1000) — ціль би не трималась.
- Перевірено на реальному коді: при виході 1 % фактична шпаруватість 1.0 %, рівно 20 фронтів за 20 с.
- 1 Гц «клацання» для SSR безпечне (це не механічне реле). Для меншого блимання в мережі можна зменшити `HEATER_WINDOW_MS`, але тоді фронт почне округлюватись до 1 мс `loop` — практично достатньо.

### Помпа

Без змін від `005`: `A0` → 0…100 % → обернена RMS-крива диммера (`powerPercentToDimmerLevel()`), гістерезис 2 рівня. На OLED потужність помпи **не** виводиться (за вимогою), її видно в Serial у полях `pump_pct` / `dimmer_0_255`.

### Кнопки

Не зчитуються. Лінії `D8`/`D9` = `INPUT_PULLUP`, Arduino їх не тягне в `LOW` і не сканує — штатна матриця кавоварки не заважається.

### Watchdog

`wdt_enable(WDTO_2S)` у `setup`, `wdt_reset()` на початку `loop`. Зависання → reset → `D4` LOW у перших рядках `setup` (до ініціалізації периферії), диммер скидається на 0 і одразу виставляється за потенціометром. `MCUSR = 0; wdt_disable();` на початку `setup` прибирає цикл перезавантажень після watchdog-reset.

## Serial (115200)

```text
# EC685 thermoblock PI heater + pump (buttons ignored)
# t_ms,Tt_C,temp_valid,set_C,heater_pct,heater_on,pump_pct,dimmer_0_255
5120,22.25,1,93.0,100,1,0,0
5620,26.75,1,93.0,100,1,0,0
8120,92.00,1,93.0,9,0,0,0
8620,93.25,1,93.0,0,0,0,0
```

| Поле | Опис |
| --- | --- |
| `t_ms` | `millis()` |
| `Tt_C` | температура термоблоку, `nan` = помилка зчитування |
| `temp_valid` | `1` = показання валідне для регулятора, `0` = ТЕН заблоковано |
| `set_C` | задана температура з `A1` |
| `heater_pct` | вихід ПІ = середня потужність ТЕНу, 0…100 |
| `heater_on` | фактичний стан `D4` у момент логування |
| `pump_pct` | поточна (згладжена) потужність помпи, 0…100 |
| `dimmer_0_255` | фактично застосований рівень диммера (0…240) |

Графік: [`scripts/004_plot_temps.py`](../scripts/004_plot_temps.py) працює без змін — він бере `parts[1]` як `Tt`, а це саме друга колонка:

```bash
python3 scripts/004_plot_temps.py --port /dev/ttyUSB0 --save
```

## Налаштування ПІ на реальній машині

1. Прошити, увімкнути Serial, поставити ручку `A1` на бажану температуру (напр. `S=93`).
2. Дивитись перший розгін: `heater_pct` має впасти зі 100 % **до** того, як `Tt` дійде до цілі. Якщо вихід падає вже після — `Kp` замалий, буде перегрів.
3. **Перерегулювання > 2 °C** → збільшити `HEATER_KP` (напр. 6–8) або зменшити `HEATER_KI` (0.03).
4. **Повзе повільно / нудотно сходиться** → збільшити `HEATER_KI` (0.08–0.12).
5. **Коливається навколо цілі** (пила ±1–2 °C) → зменшити `HEATER_KP` або розширити `HEATER_DEADBAND_C` до 0.75.
6. Сталий `heater_pct` при 93 °C на «теплому» блоці зазвичай **3–10 %** (це втрати в довкілля). Якщо 0 % і температура повзе вниз — блок віддає тепло, все нормально; якщо 0 % і температура тримається — добре.

Все калібрування — лише ці три константи на початку файлу: `HEATER_KP`, `HEATER_KI`, `HEATER_DEADBAND_C`.

## Типові проблеми

| Симптом | Ймовірна причина | Що зробити |
| --- | --- | --- |
| `Tt=---`, `temp_valid=0`, ТЕН не гріє | Термопара не на `A2`, обрив, немає живлення модуля | Перевірити `A2`/`D12`/`D13`, VCC/GND |
| `Tt=0.0C`, у Serial `# WARN Tt=0.0` | CS другої термопари (`D11`) «плаває» → конфлікт на SO | Перевірити `D11` = `OUTPUT` + `HIGH` |
| `Tt` показує кімнатну при гарячому блоці | Модулі переплутані місцями | Поміняти CS `A2` ↔ `D11` |
| ТЕН не гріє, `P=0%`, `S=20` | Ручка `A1` у мінімумі (нагрів вимкнено) | Повернути ручку |
| ТЕН не гріє, `P=0%`, `S=93`, `temp_valid=1` | Блок уже вище цілі, або вийшов `SAFETY_CUTOFF_C` | Нормально / дати охолонути |
| Температура «пиляє» ±2 °C | `Kp` завеликий / `Ki` завеликий | Зменшити `HEATER_KP` або `HEATER_KI` |
| Перегрів на 5–8 °C на старті | Накопичений інтеграл (не має бути — anti-windup) або `Kp` замалий | Перевірити `HEATER_KP ≥ 4` |
| Показник `P` стрибає на кілька % | Шум АЦП термопари | Нормально; розширити `HEATER_DEADBAND_C` |
| OLED чорний, `# OLED init failed` | Адреса не `0x3C`, `A4`/`A5` переплутані | I2C scanner |
| Перезавантаження кожні 2 с | Watchdog: `loop` довше 2 с | Перевірити I2C-шину OLED |

## Безпека

> ⚠️ 220 В AC і ТЕН ~1350 Вт. Ця прошивка **реально керує нагрівом** — на відміну від `003`/`005`, де ТЕН був заблокований.

1. **Спочатку без силового живлення ТЕНу.** У Serial `heater_pct` має падати зі 100 % до ≤10 % у міру нагріву (можна імітувати феном / гарячою водою на термопарі), `P` на екрані — змінюватись, `D4` — мультиметром клацати з періодом 1 с.
2. **Перевірити захист:** від'єднати термопару → `Tt=---`, `P=0%`; замкнути/від'єднати CS бачка → `Tt=0.0C`, `P=0%`. В обох випадках ТЕН має бути `LOW`.
3. **Перевірити аварійне вимкнення:** витягнути живлення Ардуїно під час нагріву — SSR має закритись (оптопара без сигналу).
4. Лише потім підключати ТЕН під наглядом і з термометром-референсом на корпусі.
5. Переконатись, що `SAFETY_CUTOFF_C = 105 °C` вище вашої робочої цілі й нижче межі безпеки термоблоку/пластику.

Це стенд для калібрування, а не готова робоча прошивка кавоварки: немає флоуметра, немає feed-forward за потоком, немає реакції на кнопки/пару.
