# Button Panel Tester (`scripts/009_button_panel.cpp`)

Прошивка для **окремої** Arduino Nano, яка керує штатною платою кнопок DeLonghi EC685 (3 кнопки + 4 LED) і віддає події натискань на ПК по USB та основній Arduino по UART.

Актуальна версія — **009**. `007` і `008` не працюють із реальною платою (див. «Чому попередні версії не бачили кнопок»).

| Пункт | Реалізація |
| --- | --- |
| Спокій | LED1 → LED2 → LED3 → LED4 по черзі, крок **150 мс** |
| Натискання | горить **лише** LED цієї кнопки **2000 мс**, решта гасне |
| Після утримання | чергування продовжується з LED, наступного за утримуваним |
| USB → ПК | `115200`, текст із виміряним рівнем і базою |
| UART → основна Nano | `D6 → D9`, `19200`, `B1P`/`B1R`/`B2P`/`B2R`/`BSP`/`BSR` |
| Антибрязкіт | 3 послідовні збіги × 10 мс = **30 мс** |
| Watchdog | 2 с: зависання → reset → лінії в hi-Z, LED гаснуть |

---

## Що показав вимір мультиметром

> «Подав HIGH на `D8` (Pin2), натиснув кнопку 1 — на `D4` (Pin5) стало 4.8 В. Так само натиснув кнопку 2 — на `D12` (Pin6) 4.8 В.»

Це два висновки, і обидва ламали попередні прошивки.

**1. Спільна точка кнопок — `Pin2`, а не `Pin6`.** Ваш дослід показує, що кнопка з'єднує свою лінію з вузлом на `Pin2`. Тобто кожна кнопка — це «Pin2 ↔ своя лінія»:

| Кнопка | Лінія | Підтверджено |
| --- | --- | --- |
| «1 еспресо» | Pin2 ↔ Pin5 | ✅ вашим виміром |
| «2 еспресо» | Pin2 ↔ Pin6 | ✅ вашим виміром |
| «пар» | Pin2 ↔ Pin4 або Pin2 ↔ Pin6 | ❓ перевірити командою `G` |

`007` шукав з'єднання `Pin5↔Pin6` і `Pin4↔Pin6` — між лініями, які **напряму не з'єднані ніколи**. Тому він і не бачив нічого, крім випадкового збігу для кнопки 1.

**2. Ланцюг проводить тільки «від Pin2».** У ньому стоїть діод анодом до Pin2. Тому тягнути лінію вниз (що робив `007`: `OUTPUT LOW` на Pin5 і підтяжка на Pin6) — марно, діод закритий. Потрібно навпаки: **подавати напругу на Pin2 і читати, що прийшло**.

---

## Чому не можна просто повторити мультиметр

Якби `Pin2 = OUTPUT HIGH`, а лінію кнопки притиснути до землі (щоб АЦП мав від чого рахувати), то при натиснутій кнопці струм ішов би `5 В → діод → кнопка → земля` без жодного резистора — приблизно **55 мА**, за межами абсолютного максимуму AVR (40 мА на пін).

Тому джерело — не `OUTPUT HIGH`, а `INPUT_PULLUP`: ті самі 5 В, але через 30 кОм. Максимальний струм у будь-якому ланцюзі **0.17 мА**, а на результаті це не позначається — вхідний опір АЦП у сотні мегаом, падіння на ньому нульове.

## Метод вимірювання

```cpp
uint16_t measureLine(uint8_t source, uint8_t sense) {
  allLinesHighZ();

  pinMode(LINE_PINS[source], INPUT_PULLUP);      // 5 В через 30 кОм

  digitalWrite(LINE_PINS[sense], LOW);           // розряд вузла до 0
  pinMode(LINE_PINS[sense], OUTPUT);
  delayMicroseconds(DISCHARGE_US);

  pinMode(LINE_PINS[sense], INPUT);              // hi-Z
  delayMicroseconds(CHARGE_US);                  // шлях є → заряджається

  ... analogRead(LINE_PINS[sense]) ...
}
```

Чотири кроки, кожен важливий:

| Крок | Навіщо |
| --- | --- |
| `source = INPUT_PULLUP` | 5 В без ризику струму |
| `sense = OUTPUT LOW` | розряджає вузол, щоб нез'єднана лінія читала `0`, а не шум |
| `sense = INPUT` | hi-Z: далі вузол ніхто не тримає, заряд визначає лише ланцюг |
| `analogRead` після 100 мкс | заряд встигає пройти через 30 кОм + діод |

Очікувані показники (0…1023):

| Стан | Рівень |
| --- | --- |
| не натиснуто, лінія вільна | ≈ 0 |
| натиснуто через діод | ≈ 900 |
| Pin4 (там ще катод LED2) | ≈ 700 |
| Pin4, кнопка «пар» натиснута | ≈ 900 (діод шунтує LED) |

Порівняння йде не з абсолютним порогом, а з **власною базою** кожної лінії, знятою на старті — це автоматично компенсує і напругу живлення, і фонову провідність через світлодіод. База повільно підтягується до поточного рівня, поки кнопка відпущена (компенсація нагріву й дрейфу).

## Піни

| Пін плати | Функція | Nano |
| --- | --- | --- |
| Pin 1 | аноди LED3 / LED4 | `A0` |
| Pin 2 | аноди LED1 / LED2 + **спільний вузол кнопок** | `A1` |
| Pin 3 | катоди LED1 / LED3 | `A2` |
| Pin 4 | катоди LED2 / LED4 + ланцюг кнопки «пар» | `A3` |
| Pin 5 | ланцюг кнопки «1 еспресо» | `A4` |
| Pin 6 | ланцюг кнопки «2 еспресо» / «пар» | `A5` |
| — | UART TX → основна Nano | `D6` → `D9` |
| — | UART RX (резерв) | `D5` ← `D8` |
| — | USB ↔ ПК | USB-міст |

> ⚠️ **Чому `A0…A5`, а не `D7…D12`.** Потрібен `analogRead`, а він на ATmega328P є тільки на `A0…A7`. `D7…D12` аналог читати не вміють. `D2`–`D4` лишаються вільними, `D6` — під SoftwareSerial TX.
>
> ⚠️ `A4`/`A5` — апаратні `SDA`/`SCL`. На цій Nano OLED немає, конфлікту нема. Якщо колись знадобиться I2C — лінії доведеться перенести.

## Налагодження: команда `G`

Головний інструмент. Друкує матрицю 6×6 «джерело 5 В × що читаємо»:

```
  5В\чит  Pin1  Pin2  Pin3  Pin4  Pin5  Pin6
  Pin1     ---     0     0     0     0     0
  Pin2       0   ---     0   700   900     0
  Pin3       0     0   ---     0     0     0
  ...
```

Натиснути кнопку «пар» і подивитись, у якій клітинці рядка `Pin2` стрибнуло до ~900. Це і є її лінія. Далі:

```
W232         ← «пар» → Pin2 (джерело) → Pin3
X33          ← «пар» → LED3
M            ← перевірити розводку
```

## Команди з ПК (Serial Monitor, 115200, «Newline»)

| Команда | Дія |
| --- | --- |
| `G` | карта 6×6 — яка лінія з якою з'єднана |
| `D` | безперервний показ рівнів і баз, увімк/вимк |
| `C` | перекалібрувати бази (кнопки відпущені) |
| `W<кноп><src><чит>` | задати лінії кнопці, напр. `W214` |
| `X<кноп><LED>` | задати LED кнопці, напр. `X12` |
| `L1`…`L4` | примусово LED на 5 с |
| `T` | прогін LED1 → LED4 по 0.7 с |
| `A` | авто-чергування |
| `M` | показати розводку |
| `?` | довідка |

Перепризначення діє до перезавантаження. Щоб закріпити — змініть початкові `buttons[]` і `ledForButton[]` у скетчі.

## Протокол UART до основної Arduino

`19200 8N1`, 4 байти + `\n`:

| Рядок | Значення |
| --- | --- |
| `B1P` / `B1R` | «1 еспресо» натиснута / відпущена |
| `B2P` / `B2R` | «2 еспресо» натиснута / відпущена |
| `BSP` / `BSR` | «пар» натиснута / відпущена |

`SoftwareSerial::write()` передає байт з вимкненими перериваннями (~0.52 мс при 19200), тому рядок свідомо короткий. Тривалість натискання основна сторона міряє сама: `P` → `R`.

Приймач на основній Nano (`D9` ← `D6` плати кнопок):

```cpp
#include <SoftwareSerial.h>
SoftwareSerial links(9, 8);   // RX = D9 (від D6 плати кнопок), TX = D8

void setup() {
  Serial.begin(115200);
  links.begin(19200);
}

void loop() {
  static char buf[8];
  static uint8_t len = 0;

  while (links.available() > 0) {
    const char c = (char)links.read();

    if (c != '\n') {
      if (len < sizeof(buf) - 1) buf[len++] = c;
      continue;
    }

    buf[len] = '\0';
    if (len == 3 && buf[0] == 'B') {
      Serial.print(F("button "));
      Serial.print(buf[1]);
      Serial.println(buf[2] == 'P' ? F("pressed") : F("released"));
    }
    len = 0;
  }
}
```

> ⚠️ На основній Nano `D8`/`D9` у `readme.md` зайняті під кнопку 1. Поки це тест-стенд; при зведенні плат лінк треба перенести.

## Збирання

1. Arduino IDE → Board: **Arduino Nano**, Processor: **ATmega328P** (або `Old Bootloader` для клонів).
2. Відкрити [`scripts/009_button_panel.cpp`](../scripts/009_button_panel.cpp).
3. Бібліотеки не потрібні — `SoftwareSerial` входить у пакет AVR.
4. Flash ≈ **9.7 КБ**, RAM ≈ **0.5 КБ** із 2 КБ.

---

## Порядок налагодження

1. Шість ліній плати → `A0…A5`, шлейф від'єднати від `J8`.
2. Подати живлення — має початись чергування LED.
3. `T` — перевірити, що всі чотири LED світяться в правильному порядку.
4. `G` — натиснути кожну кнопку, знайти її пару `Pin2 → PinX`.
5. `W` + `X` — закріпити пари й LED, перевірити `M`.
6. Вимкнути `D`, перевірити звичайну роботу: чергування → натискання → 2 с сталого LED.
7. `D6` → `D9` основної, `GND` спільний, перевірити `B1P`…`BSR`.

## Застереження

- **Шлейф плати кнопок обов'язково від'єднати від штатної плати (роз'єм `J8`).** Інакше виходи `PIC16F1936` і виводи Nano одночасно тягнутимуть ті самі шість ліній — конфлікт виходів.
- Плата кнопок — **пасивна матриця**: 3 кнопки + 4 LED на шести лініях, без власного живлення. Arduino живить її повністю через ці лінії, тому **спільний `GND` з кавоваркою не потрібен** (і небезпечний — див. нижче).
- ⚠️ **Головне про безпеку.** Штатний блок живлення кавоварки — безтрансформаторний (`LNK304GN`), тому його «5 В» і «GND» гальванічно **не** розв'язані від мережі. Якщо з'єднати `GND` Arduino (а отже й землю ПК через USB) з будь-якою точкою штатної плати — потенціал мережі піде в USB-порт комп'ютера. Живити Arduino тільки від USB і ніколи не з'єднувати його землю зі штатною платою.
- **Послідовні резистори 220…330 Ом на всіх шести лініях** між Arduino і платою. Потрібні вони не для вимірювання (там 0.17 мА), а для LED: анодний вивід віддає 5…15 мА.
- Ніколи не тримайте анод і катод так, щоб усі чотири LED увімкнулись паралельно — струм піде через один пін. Прошивка цього не робить: завжди рівно один активний LED.
- Уся логіка — без `delay()`: інакше антибрязкіт і анімація розсинхронізуються.
- Якщо плата перезавантажується циклічно (старі Nano не скидають прапорець WDT), поставте `USE_WATCHDOG 0`.
- Якщо при старті замість калібрування видно «база=0» для всіх кнопок — перевірте, що шлейф справді на `A0…A5`, а не на `D7…D12`.
