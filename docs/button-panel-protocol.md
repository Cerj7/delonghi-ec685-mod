# Протокол зв’язку: плата кнопок ↔ основна Arduino

Контракт UART між Arduino Nano, яка керує штатною панеллю кнопок EC685, і основною Arduino Nano (термоблок / помпа / логіка приготування).

| Параметр | Значення |
| --- | --- |
| Фізика | UART `8N1`, `19200` бод |
| Лінії | Плата кнопок `D6` (TX) → основна `D9` (RX) |
| | Плата кнопок `D5` (RX) ← основна `D8` (TX) |
| | Спільний `GND` між двома Nano (не зі штатною платою кавоварки) |
| Формат кадру | ASCII-рядок без пробілів, закінчується `\n` (`\r` ігнорується) |
| Макс. довжина коду | 3 символи + `\n` |
| Джерело істини для LED | **тільки команди основної плати**; натискання кнопок лише генерують події |

Прошивки: [`scripts/011_button_panel_ui.cpp`](../scripts/011_button_panel_ui.cpp) (панель), [`scripts/012_main_panel_link.cpp`](../scripts/012_main_panel_link.cpp) (тестова заглушка основної).

---

## Чому короткі коди, а не текст

`SoftwareSerial` на AVR передає кожен байт із вимкненими перериваннями (~0.52 мс на байт при 19200). Довгі українські фрази «заморожували» б `millis()` і сканування матриці кнопок/LED. Трилітерні коди читабельні в Serial Monitor і дешеві по часу.

Обидві сторони можуть дублювати кадри в USB Serial (`115200`) для налагодження — це не частина контракту між платами.

## Панель → основна (події кнопок)

Надсилаються **лише по фронту натискання** (антибрязкіт на панелі). Відпускання не передається.

| Код | Значення |
| --- | --- |
| `B1` | Натиснуто «1 Еспресо» |
| `B2` | Натиснуто «2 Еспресо» |
| `B3` | Натиснуто «Пар» |

Панель **не** вирішує, що саме робити з натисканням (нагрів / пролив / скасування). Вона завжди шле `B1`/`B2`/`B3`; основна плата інтерпретує подію у своєму стані й відповідає командою індикації.

Типові сценарії на основній:

| Стан основної | Подія | Очікувана відповідь на панель |
| --- | --- | --- |
| Готово до еспресо | `B1` | `P11` (старт проливу 1) |
| Готово до еспресо | `B2` | `P21` |
| Йде пролив 1/2 | `B1` / `B2` / `B3` | за логікою основної (скасування тощо); панель лише шле подію |
| Холодний / потрібен пар | `B3` | `HS1` (нагрів пару) |
| Пар розігрітий, очікує подачу | `B3` | `SS1` (подача пару) |

## Основна → панель (команди індикації)

| Код | Значення | Дія LED на панелі |
| --- | --- | --- |
| `HE1` | Починаю нагрів для еспресо | LED1 і LED2 **мигають**; LED3/LED4 не змінюються цією командою (LED4 — див. правила нижче) |
| `HE0` | Завершено нагрів для еспресо | LED1 і LED2 **постійно** |
| `P11` | Починаю приготування 1 еспресо | LED1 **мигає** |
| `P10` | Завершено приготування 1 еспресо | LED1 **постійно** |
| `P21` | Починаю приготування 2 еспресо | LED2 **мигає** |
| `P20` | Завершено приготування 2 еспресо | LED2 **постійно** |
| `HS1` | Починаю нагрів для пару | LED3 **мигає** |
| `HS0` | Завершено нагрів для пару | LED3 **постійно** |
| `SS1` | Починаю подачу пару | LED3 **мигає** |
| `SS0` | Завершено подачу пару | LED3 **постійно** |
| `DC1` | Необхідна декальцинація | Запит на мигання LED4 (див. пріоритети) |
| `DC0` | Декальцинація завершена | LED4 **вимкнено**, прапорець знято |

Початковий стан після reset панелі: **усі LED вимкнені**, прапорець декальцинації знято.

---

## Пріоритети LED4 (декальцинація)

`DC1` запам’ятовується. LED4 мигає **лише якщо** жоден із блокувальних процесів не активний:

| Блокує мигання LED4 | Поки активна команда-стан |
| --- | --- |
| Приготування еспресо | після `P11` до `P10`, або після `P21` до `P20` |
| Нагрів пару | після `HS1` до `HS0` |
| Подача пару | після `SS1` до `SS0` |

Не блокує: нагрів еспресо (`HE1`…`HE0`), «готовий» стан еспресо/пару (постійні LED).

Коли блокувальний процес закінчується, а `DC1` досі дійсний — мигання LED4 **відновлюється** автоматично.
`DC0` гасить LED4 і знімає запит.

## Машина станів індикації (панель)

```
RESET ──► ALL OFF
            │
            │ HE1
            ▼
     LED1+LED2 BLINK ──HE0──► LED1+LED2 SOLID
                                   │
                    ┌──────────────┼──────────────┐
                    │ P11          │ P21          │ HS1 (з B3)
                    ▼              ▼              ▼
              LED1 BLINK     LED2 BLINK     LED3 BLINK
                    │ P10          │ P20          │ HS0
                    ▼              ▼              ▼
              LED1 SOLID     LED2 SOLID     LED3 SOLID
                                                  │ B3 → SS1
                                                  ▼
                                            LED3 BLINK
                                                  │ SS0
                                                  ▼
                                            LED3 SOLID
```

`DC1`/`DC0` ортогональні цій схемі (окремий прапорець + LED4).

## Приклад діалогу

```
основна → панель : HE1          # користувач увімкнув машину / старт нагріву
панель  LED      : LED1+LED2 мигають
основна → панель : HE0
панель  LED      : LED1+LED2 постійно

користувач       : «1 Еспресо»
панель  → основна: B1
основна → панель : P11
панель  LED      : LED1 мигає (LED2 лишається постійним)
основна → панель : P10
панель  LED      : LED1 постійно

користувач       : «Пар»
панель  → основна: B3
основна → панель : HS1
панель  LED      : LED3 мигає
основна → панель : HS0
панель  LED      : LED3 постійно

користувач       : «Пар» знову
панель  → основна: B3
основна → панель : SS1
панель  LED      : LED3 мигає
основна → панель : SS0
панель  LED      : LED3 постійно
```

## Помилки й ігнорування

- Невідомий код → ігнор (панель пише попередження в USB Serial).
- Повторна команда того самого стану (напр. другий `HE0`) → ідемпотентна, LED просто підтверджують стан.
- Кадр довший за буфер або без `\n` → відкидається при переповненні.
- Обидві сторони мають право слати кадри в будь-який момент; колізій half-duplex UART на двох дротах немає (роздільні TX/RX).

## Тестування зі стенда

1. Залити [`011_button_panel_ui.cpp`](../scripts/011_button_panel_ui.cpp) на Nano панелі.
2. Залити [`012_main_panel_link.cpp`](../scripts/012_main_panel_link.cpp) на основну Nano.
3. З’єднати `D6↔D9`, `D5↔D8`, `GND↔GND`.
4. У Serial Monitor основної (`115200`) слати ті самі коди (`HE1`, `HE0`, …) — вона прозоро форвардить їх на панель і друкує вхідні `B1`/`B2`/`B3`.
