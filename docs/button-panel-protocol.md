# Протокол зв’язку: плата кнопок ↔ основна Arduino

Контракт UART між Arduino Nano, яка керує штатною панеллю кнопок EC685, і основною Arduino Nano (термоблок / помпа / логіка приготування).

| Параметр | Значення |
| --- | --- |
| Фізика | UART `8N1`, `19200` бод |
| Лінії | Плата кнопок `D6` (TX) → основна `D9` (RX) |
| | Плата кнопок `D5` (RX) ← основна `D8` (TX) |
| | Спільний `GND` між двома Nano (не зі штатною платою кавоварки) |
| Формат кадру | ASCII-рядок без пробілів, закінчується `\n` (`\r` ігнорується) |
| Макс. довжина коду | 3 символи + `\n` |
| Джерело істини для LED | **тільки команди основної плати**; натискання кнопок лише генерують події |

Прошивки: [`scripts/011_button_panel_ui.cpp`](../scripts/011_button_panel_ui.cpp) (панель), [`scripts/013_main_brew_logic.cpp`](../scripts/013_main_brew_logic.cpp) (основна логіка), [`scripts/012_main_panel_link.cpp`](../scripts/012_main_panel_link.cpp) (тестова заглушка основної для стенда лінка).

Дельта hold «пар» / декальцинація: [`specs/002-descaling-program/contracts/panel-hold-uart.md`](../specs/002-descaling-program/contracts/panel-hold-uart.md).

---

## Чому короткі коди, а не текст

`SoftwareSerial` на AVR передає кожен байт із вимкненими перериваннями (~0.52 мс на байт при 19200). Довгі українські фрази «заморожували» б `millis()` і сканування матриці кнопок/LED. Трилітерні коди читабельні в Serial Monitor і дешеві по часу.

Обидві сторони можуть дублювати кадри в USB Serial (`115200`) для налагодження — це не частина контракту між платами.

## Панель → основна (події кнопок)

`B1` / `B2` — **лише по фронту натискання** (антибрязкіт на панелі; release-код не шлеться).

Кнопка «пар» — **press + release**: на підтверджений press → `B3`, на підтверджений release → `R3` (debounce локально на панелі). Тривалість утримання й рішення «короткий пар vs hold-enter декальцинації» рахує **лише основна** (`013`); панель **не** міряє 1 с / 10 с і **не** шле `H3`/`D3`.

| Код | Коли | Значення |
| --- | --- | --- |
| `B1` | Rising edge «1 Еспресо» | Натиснуто «1 Еспресо» |
| `B2` | Rising edge «2 Еспресо» | Натиснуто «2 Еспресо» |
| `B3` | Rising edge «пар» | Початок натискання «Пар» |
| `R3` | Falling edge «пар» | Відпускання «Пар» (`002`) |

Панель **не** вирішує, що саме робити з натисканням (нагрів / пролив / скасування / декальцинація). Вона завжди шле `B1`/`B2`/`B3`/`R3` за правилами вище; основна плата інтерпретує подію у своєму стані й відповідає командою індикації.

Типові сценарії на основній:

| Стан основної | Подія | Очікувана відповідь на панель |
| --- | --- | --- |
| Готово до еспресо | `B1` | `P11` (старт проливу 1) |
| Готово до еспресо | `B2` | `P21` |
| Йде пролив 1/2 | `B1` / `B2` / `B3` | за логікою основної (скасування тощо); панель лише шле подію |
| Холодний / потрібен пар | `B3` | `HS1` (нагрів пару) |
| Пар розігрітий, очікує подачу | `B3` | `SS1` (подача пару) |
| Після пару, термоблок занадто гарячий | — | `LT1` (охолодження); далі `LT0` |

## Основна → панель (команди індикації)

| Код | Значення | Дія LED на панелі |
| --- | --- | --- |
| `HE1` | Починаю нагрів для еспресо | LED1 і LED2 **мигають**; LED3/LED4 не змінюються цією командою (LED4 — див. правила нижче) |
| `HE0` | Завершено нагрів для еспресо | LED1 і LED2 **постійно** |
| `P11` | Починаю приготування 1 еспресо | LED1 **мигає** |
| `P10` | Завершено приготування 1 еспресо | LED1 **постійно** |
| `P21` | Починаю приготування 2 еспресо | LED2 **мигає** |
| `P20` | Завершено приготування 2 еспресо | LED2 **постійно** |
| `HS1` | Починаю нагрів для пару | LED3 **мигає** |
| `HS0` | Завершено нагрів для пару | LED3 **постійно** |
| `SS1` | Починаю подачу пару | LED3 **мигає** |
| `SS0` | Завершено подачу пару | LED3 **постійно** |
| `LT1` | Необхідно знизити температуру (після пару термоблок занадто гарячий для еспресо) | LED3 **подвійні блимки** (блім-блім–пауза) |
| `LT0` | Зниження температури завершено | LED3 **вимкнено** |
| `DC1` | Необхідна декальцинація | Запит на мигання LED4 (див. пріоритети) |
| `DC0` | Декальцинація завершена | LED4 **вимкнено**, прапорець знято |

Початковий стан після reset панелі: **усі LED вимкнені**, прапорець декальцинації знято.

---

## Пріоритети LED4 (декальцинація)

`DC1` запам’ятовується. LED4 мигає **лише якщо** жоден із блокувальних процесів не активний:

| Блокує мигання LED4 | Поки активна команда-стан |
| --- | --- |
| Приготування еспресо | після `P11` до `P10`, або після `P21` до `P20` |
| Нагрів пару | після `HS1` до `HS0` |
| Подача пару | після `SS1` до `SS0` |

Не блокує: нагрів еспресо (`HE1`…`HE0`), «готовий» стан еспресо/пару (постійні LED).

Коли блокувальний процес закінчується, а `DC1` досі дійсний — мигання LED4 **відновлюється** автоматично.
`DC0` гасить LED4 і знімає запит.

## Машина станів індикації (панель)

```
RESET ──► ALL OFF
            │
            │ HE1
            ▼
     LED1+LED2 BLINK ──HE0──► LED1+LED2 SOLID
                                   │
                    ┌──────────────┼──────────────┐
                    │ P11          │ P21          │ HS1 (з B3)
                    ▼              ▼              ▼
              LED1 BLINK     LED2 BLINK     LED3 BLINK
                    │ P10          │ P20          │ HS0
                    ▼              ▼              ▼
              LED1 SOLID     LED2 SOLID     LED3 SOLID
                                                  │ B3 → SS1
                                                  ▼
                                            LED3 BLINK
                                                  │ SS0
                                                  ▼
                                            LED3 SOLID
                                                  │ LT1 (термоблок занадто гарячий)
                                                  ▼
                                         LED3 DOUBLE-BLINK
                                                  │ LT0
                                                  ▼
                                            LED3 OFF
```

`DC1`/`DC0` ортогональні цій схемі (окремий прапорець + LED4).
Під час `LT1`…`LT0` звичайне мигання пару (`HS*`/`SS*`) для LED3 замінюється подвійними блимами.

## Приклад діалогу

```
основна → панель : HE1          # користувач увімкнув машину / старт нагріву
панель  LED      : LED1+LED2 мигають
основна → панель : HE0
панель  LED      : LED1+LED2 постійно

користувач       : «1 Еспресо»
панель  → основна: B1
основна → панель : P11
панель  LED      : LED1 мигає (LED2 лишається постійним)
основна → панель : P10
панель  LED      : LED1 постійно

користувач       : «Пар»
панель  → основна: B3
основна → панель : HS1
панель  LED      : LED3 мигає
основна → панель : HS0
панель  LED      : LED3 постійно

користувач       : «Пар» знову
панель  → основна: B3
основна → панель : SS1
панель  LED      : LED3 мигає
основна → панель : SS0
панель  LED      : LED3 постійно

основна → панель : LT1          # після пару треба охолодити термоблок
панель  LED      : LED3 подвійні блимки
основна → панель : LT0
панель  LED      : LED3 вимкнено
```

## Помилки й ігнорування

- Невідомий код → ігнор (панель пише попередження в USB Serial).
- Повторна команда того самого стану (напр. другий `HE0`) → ідемпотентна, LED просто підтверджують стан.
- Кадр довший за буфер або без `\n` → відкидається при переповненні.
- Обидві сторони мають право слати кадри в будь-який момент; колізій half-duplex UART на двох дротах немає (роздільні TX/RX).

## Hold «пар» / `R3` (`002-descaling-program`)

Контракт дельти: [`contracts/panel-hold-uart.md`](../specs/002-descaling-program/contracts/panel-hold-uart.md). Логіка станів hold/prep/фаз — на основній (`013`); панель лишається «тупою» щодо режиму (**FR-018**).

| Подія на дроті | Типова інтерпретація на `013` (скорочено) |
| --- | --- |
| `B3` з `ESPRESSO_READY` / `ESPRESSO_HEAT` | Старт hold-жесту (`DESCALE_HOLD`); **не** одразу `enterSteam()` |
| `R3`, утримання &lt; prompt (~1 с) | Коротке «пар» → штатний steam path (`001`) |
| `R3`, prompt ≤ утримання &lt; enter (~10 с) | Скасувати відлік; без пару і без програми |
| Утримання ≥ enter | `DESCALE_PREP` (навіть без `R3`); подальше `R3` програму **не** скасовує |
| `B3` у prep / refill / wait-rinse | Коротке підтвердження фази (за відкритої ручки); `R3` у цих станах — ігнор |
| `R3` без активного hold-жесту | no-op; у brew/steam/`FAULT` `B3` — за матрицею `001` |

### Пара прошивок (FR-018a / SC-008)

Поставка фічі `002` **MUST** оновлювати панель і основну **разом** (`011` з `R3` + `013` з hold-enter). Acceptance hold-enter і short-vs-hold — лише на стенді з **парою** оновлених прошивок (**SC-008**). Конфігурація «стара панель без `R3` + нова main» для `002` **не** підтримується (**FR-018a**).

### Сумісність прошивок

| Панель | Основна | Поведінка |
| --- | --- | --- |
| Стара (без `R3`) | Нова (`013` / `002`) | Hold-enter **неможливий**; short `B3` може лишитись press-immediate — **не підтримується** для `002` |
| Нова (`R3`) | Стара (без парсера `R3`) | Зайві `R3` ігноруються (невідомий код / no-op); brew/steam `001` не ламаються |
| Нова (`R3`) | Нова (`013`) | Повна семантика short vs hold / декальцинація |

## Тестування зі стенда

1. Залити [`011_button_panel_ui.cpp`](../scripts/011_button_panel_ui.cpp) на Nano панелі (**з** `R3`).
2. Для перевірки лінка індикації: [`012_main_panel_link.cpp`](../scripts/012_main_panel_link.cpp); для hold/декальцинації — **парна** [`013_main_brew_logic.cpp`](../scripts/013_main_brew_logic.cpp) (**FR-018a** / **SC-008**).
3. З’єднати `D6↔D9`, `D5↔D8`, `GND↔GND`.
4. У Serial Monitor основної (`115200`): коди індикації (`HE1`, `HE0`, …) і вхідні `B1`/`B2`/`B3`/`R3` (натискання/відпускання «пар»).
