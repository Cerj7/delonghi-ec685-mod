# DeLonghi EC685 Custom PID & Flow Control (Arduino Nano Mod)

Кастомна прошивка та гідравлічно-електронна модифікація для кавоварки **DeLonghi Dedica EC685** на базі **Arduino Nano v3**.

Мод додає можливість точного регулювання тиску/потоку помпи (dimming), вимірювання витрати води у реальному часі (флоуметр) та комбінованого керування температурою термоблока (Feed-forward + PID). Про теорію керування детальніше [тут]().

Ардуїно потрібні наступні сигнали:

| Сигнал | Навіщо |
| --- | --- |
| сигнал керування SDD термоблока зі штатного контроллера. | У випадках, коли кавомашина не готує еспресо, то Ардуїно має в точності повторювати сигнал штатного контроллера, щоб кавоварка коректно працювала в усіх режимах |
| сигнали з усіх трьох кнопок кавоварки. | Ми маємо знати, коли вмикається приготування кави (хоча якщо сигнал керування SDDтермоблока зі штатного контроллера має характерну особливість при приготуванні кави, то тоді сигнали з кнопок не треба) |
| сигнал штатного лічильника води кавоварки. | Необхідно для розрахунку керування термоблоком |
| сигнал з ручки подачі пари. | В режимі пару помпа має працювати як зазвичай (як до модифікації) АБО користувач має вручну потенціометром виставляти повну потужність помпи |
| сигнал керування помпою зі штатного контроллера. | У випадках, коли кавомашина не готує еспресо (наприклад, подача пару або очистка він накипу), то Ардуїно має в точності повторювати сигнал штатного контроллера, щоб кавоварка коректно працювала в усіх режимах |
| Термопара в бачку води | Вхідна температура $T_{\text{in}}$ для розрахунку керування термоблоком |
| Термопара на термоблоці / виході | Фактична температура нагріву / води на виході ($T_{\text{out}}$) |
| Сигнал потенціометра помпи | Зчитуємо задану користувачем потужність помпи |
| Сигнал потенціометра температури | Зчитуємо задану користувачем бажану температуру |


Ардуїно керує наступними пристроями:
1. штатне твердотільне реле (SSR) термоблоку, через штатну оптопару
2. помпою через диммер

## 📐 Схема підключення (Pinout)

Зважаючи на те, що диммер викоритовує переривання, а I2C та SPI мають свої фіксовані піни:

| Компонент | Пін Arduino Nano | Тип / Опис | Статус |
| --- | --- | --- |
| **AC Dimmer (Zero-Cross / SYNC)** | `D2` | Обов'язково пін переривання INT0 | ✅
| **AC Dimmer (GATE / PWM)** | `D3` | Вихід на симистор помпи | ✅
| **Штатне реле ТЕНу (SSR)** | `D4` | Цифровий вихід (High/Low) керування нагрівом | ✅
| **Флоуметр (Сигнал)** | `D5` | Вхід імпульсів лічильника води | ✅
| **Сигнал SDD (Штатний)** | `D6` | Вхід (через оптопару) | **Не використовується** |
| **Сигнал на помпу (Штатний)** | `A3` | Вхід (через оптопару) | **Не використовується** |
| **Кнопка 1 (Одинарна)** | `D8` | Вхід | ✅ |
| **Кнопка 1 (Одинарна)** | `D9` | Вихід | ✅ |
| **Кнопка 2 (Подвійна)** | - | Вхід (`INPUT_PULLUP` / оптопара) | **Не використовується** |
| **Кнопка 3 (Пар)** | - | Вхід (`INPUT_PULLUP` / оптопара) | **Не використовується** |
| **Ручка пари (Мікроперемикач)** | `D10` | Вхід (`INPUT_PULLUP` / оптопара) | ✅ |
| **MAX6675 #1 (CS)** — термоблок / вихід | `A2` | Chip Select першої термопари | ✅ |
| **MAX6675 #2 (CS)** — бачок води | `D11` | Chip Select другої термопари | ✅ |
| **MAX6675 (SO / MISO)** | `D12` | Data Out (спільна шина для обох модулів) | ✅ |
| **MAX6675 (SCK / CLK)** | `D13` | Clock (спільна шина для обох модулів) | ✅ |
| **Потенціометр Помпи (10k)** | `A0` | Аналоговий вхід (0–100%) | ✅ |
| **Потенціометр Температури (10k)** | `A1` | Аналоговий вхід (80.0–98.0 °C) | ✅ |
| **OLED Дисплей (SDA)** | `A4` | Лінія даних I2C | ✅ |
| **OLED Дисплей (SCL)** | `A5` | Лінія тактування I2C | ✅ |

> **Дві термопари MAX6675:** модулі ділять `D12` (SO) і `D13` (SCK); кожному потрібен окремий CS (`A2` — термоблок, `D11` — бачок). Читати по черзі (≥220 мс на конверсію кожного). `A3` — штатний сигнал помпи (цифровий вхід). `A6`/`A7` — лише аналогові входи, як CS не підходять.
>
> **Діапазон потенціометра температури (`A1`)** залежить від прошивки: у `006` це 20…100 °C (від кімнатної до максимуму), у плановій робочій версії — 80…98 °C.

## 🛠 Основний функціонал

* **Pressure/Flow Profiling:** Ручне регулювання потужності помпи (0–100%) через потенціометр та фазовий димер AC (BTA16 / Zero-Cross).
* **Predictive Thermal Control:** Алгоритм керування ТЕНом на основі математичної моделі потоку води ($P = c \cdot m \cdot \Delta T$) та двох термопар MAX6675: бачок ($T_{\text{in}}$) і термоблок / вихід ($T_{\text{out}}$).
* **Real-time Flow Measurement:** Зчитування імпульсів штатного ротаметричного лічильника води (Digmesa / Flowmeter) через переривання.
* **Інформативний OLED-дисплей:** Відображення поточної та заданої температури, потужності помпи у % та швидкості потоку у мл/с.
* **Безпечна інтеграція:** Зчитування сигналів штатної плати (кнопки, ручка пари, SDD) через опторозв'язку.

## План

1. Знайти лінію 5 В для живлення Ардуїно
2. Перевірити рівень сигналу з кнопок кавоварки, щоб зрозуміти, чи можемо ми напряму подавати сигнали на Ардуїно
3. Спробувати знайти цифровий сигнал з термопари термоблока
4. Написати скріпт, який має логувати та повторювати всі керуючі сигнали (термоблок та помпа), які ми зчитуємо з штатного мікроконтроллера
5. Підключити Ардуїно до штатного мікроконтроллера
6. Запустити кавоварку в різних режимах, щоб потім у логах проаналізувати всі форми сигналів
7. Після аналізу логів зробити висновок, чи зможемо ми лише по формі сигналу зрозуміти в якому режимі працює кавоварка в даний момент, чи нам треба буде зчитувати сигнали з кнопок
8. Написати скрипт керування потужністю помпи, щоб визначити мінімум потужності, при якій помпа може працювати. Виводить показник потужності на дисплей.
9. Написати скрипт, що виводить показники з обох термопар MAX6675 (бачок і термоблок / вихід) — [`scripts/004_dual_thermocouple.cpp`](scripts/004_dual_thermocouple.cpp) + плотер [`scripts/004_plot_temps.py`](scripts/004_plot_temps.py); док: [`docs/dual-thermocouple.md`](docs/dual-thermocouple.md)
9.1 Прошивка-стенд: потенціометр помпи керує диммером, на OLED — температура термоблоку й поточна потужність помпи, ТЕН заблокований, кнопки не зчитуються — [`scripts/005_pot_pump_temp_display.cpp`](scripts/005_pot_pump_temp_display.cpp); док: [`docs/pot-pump-temp-display.md`](docs/pot-pump-temp-display.md)
9.2 Прошивка-стенд з нагрівом: потенціометр температури задає 20…100 °C, ПІ тримає термоблок через SSR, на OLED — температура й поточна потужність ТЕНу у %, кнопки не зчитуються — [`scripts/006_thermoblock_pi_heater.cpp`](scripts/006_thermoblock_pi_heater.cpp); док: [`docs/thermoblock-pi-heater.md`](docs/thermoblock-pi-heater.md)
9.3 Окрема Nano на плату кнопок: тест кнопок і світлодіодів (чергування в спокої, 2 с горить LED натиснутої кнопки), події натискань → ПК по USB і основна Nano по UART — [`scripts/009_button_panel.cpp`](scripts/009_button_panel.cpp); док: [`docs/button-panel.md`](docs/button-panel.md)
9.4 Робоча прошивка основної Nano: розігрів → холодний пролив `B1` → еспресо `B2` з преінфузією → пар → охолодження → нагадування декальцинації; кнопки/LED через UART-панель (панель `011` без змін session 4) — [`scripts/013_main_brew_logic.cpp`](scripts/013_main_brew_logic.cpp); док: [`docs/main-brew-logic.md`](docs/main-brew-logic.md); фіча: [`specs/001-main-brew-logic/`](specs/001-main-brew-logic/)
10. Написати скрипт, що на основі форми сигналу або на основі сигналів з кнопок визначає режим роботи кавоварки в даний момент, і якщо це приготування еспрессо, то дозволяє керувати потужністю помпи та температурою. На дисплеї — $T_{\text{in}}$, $T_{\text{out}}$, потужність помпи та потік.
11. Зібрати все навісним монтажом і перевірити роботу і регулювання. Відкалібрувати
